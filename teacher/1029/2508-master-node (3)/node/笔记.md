## javascript
1. ECMAScript 是一个js脚本语言的标准
2. javascript 是 ECMAScript 的一种具体实现
3. javascript 运行在浏览器端
4. 三个核心：
- ECMA核心语法：var、let、const、if、switch、for、while
- BOM：浏览器对象模型
- DOM: 文档对象模型


## nodejs
1. nodejs 是 ECMAScript 的另一种具体实现，是一个可以在服务端运行 js 文件的应用程序
2. nodejs 运行在服务器端
3. 内置一些包可以操作文件、创建服务器应用...
4. 安装 node 之后自带一个包管理工具 npm
- 查看当前 node 版本 `node -v`
- 查看当前 npm 版本 `npm -v`
5. 在终端运行 js 文件 `node 文件路径`

## 常用命令
1. `cd 文件目录` 切换当前终端的路径
2. `pwd` 查看当前终端所在的文件夹路径
3. `ls` 查看当前文件夹的所有文件, `ls -a` 查看所有文件，包括隐藏文件

## CommonJS 规范（node中的模块化规范）
1. 每一个 js 都是一个单独的模块，每个文件中的变量不会互相影响
2. `const a = require('文件路径')` 引入其他 js 文件，获取该文件抛出的变量
3. `module.exports = 抛出的内容` 抛出内容
4. `exports.属性名 = 内容` 单独抛出


## fs 模块常用方法总结

> `fs`（File System）模块用于与文件系统进行交互，提供文件的读写、删除、重命名、目录操作等功能。  
> Node.js 同时提供 **异步**（非阻塞）和 **同步**（阻塞）版本的方法。  
> 异步方法通常带有回调函数或返回 Promise。
- 注意：fs 操作文件时最好写绝对路径，如果使用相对路径是相对于执行命令行时所在终端的路径，并不是相对于当前文件

---

### 📂 文件读写相关

| 方法 | 描述 | 类型 | 示例 |
|------|------|------|------|
| `fs.readFile(path, [options], callback)` | 异步读取文件内容 | 异步 | `fs.readFile('test.txt', 'utf8', (err, data) => console.log(data));` |
| `fs.readFileSync(path, [options])` | 同步读取文件内容 | 同步 | `const data = fs.readFileSync('test.txt', 'utf8');` |
| `fs.writeFile(path, data, [options], callback)` | 异步写入文件，覆盖原内容 | 异步 | `fs.writeFile('test.txt', 'Hello', () => console.log('写入完成'));` |
| `fs.writeFileSync(path, data, [options])` | 同步写入文件 | 同步 | `fs.writeFileSync('test.txt', 'Hello');` |
| `fs.appendFile(path, data, [options], callback)` | 追加内容到文件末尾 | 异步 | `fs.appendFile('log.txt', '新日志\n', () => {});` |
| `fs.appendFileSync(path, data, [options])` | 同步追加文件内容 | 同步 | `fs.appendFileSync('log.txt', '新日志\n');` |

---

### 🧾 文件信息与状态

| 方法 | 描述 | 类型 | 示例 |
|------|------|------|------|
| `fs.stat(path, callback)` | 获取文件或目录信息（大小、类型、修改时间等） | 异步 | `fs.stat('test.txt', (err, stats) => console.log(stats.size));` |
| `fs.statSync(path)` | 同步获取文件信息 | 同步 | `const stats = fs.statSync('test.txt');` |
| `fs.existsSync(path)` | 判断文件或目录是否存在 | 同步 | `if (fs.existsSync('config.json')) console.log('存在');` |
| `fs.access(path, mode, callback)` | 检查文件的可访问权限 | 异步 | `fs.access('test.txt', fs.constants.R_OK, err => console.log(err ? '不可读' : '可读'));` |

## path 模块常用方法总结

> `path` 模块提供了用于处理文件和目录路径的实用工具，能够在不同操作系统（Windows / macOS / Linux）上保持一致性。  
> 它是 Node.js 的内置模块，无需安装，直接使用：
> ```js
> const path = require('path');
> ```

---

### 🧩 一、路径拼接与解析

| 方法 | 说明 | 示例 | 输出结果 |
|------|------|------|-----------|
| `path.join([...paths])` | 拼接多个路径片段，并规范化路径 | `path.join('a', 'b', 'c.txt')` | `'a/b/c.txt'` |
|  |  | `path.join('/a', '/b', '../c')` | `'/a/c'` |
| `path.resolve([...paths])` | 从右到左解析路径，返回绝对路径 | `path.resolve('a', 'b', 'c.txt')` | `/当前工作目录/a/b/c.txt` |
|  |  | `path.resolve('/a', 'b')` | `/a/b` |
| `path.normalize(path)` | 规范化路径（去除多余符号） | `path.normalize('a//b/../c')` | `'a/c'` |

---

### 📂 二、路径信息解析

| 方法 | 说明 | 示例 | 输出结果 |
|------|------|------|-----------|
| `path.basename(path, [ext])` | 获取路径的文件名（可去除扩展名） | `path.basename('/a/b/c.txt')` | `'c.txt'` |
|  |  | `path.basename('/a/b/c.txt', '.txt')` | `'c'` |
| `path.dirname(path)` | 获取目录名（路径所在文件夹） | `path.dirname('/a/b/c.txt')` | `'/a/b'` |
| `path.extname(path)` | 获取文件扩展名（带点） | `path.extname('index.html')` | `'.html'` |

---

### 🧱 三、路径拆分与组装

| 方法 | 说明 | 示例 | 输出结果 |
|------|------|------|-----------|
| `path.parse(path)` | 将路径解析为对象 | `path.parse('/a/b/c.txt')` | `{ root: '/', dir: '/a/b', base: 'c.txt', ext: '.txt', name: 'c' }` |
| `path.format(obj)` | 将 `parse` 解析的对象重新组装成路径 | `path.format({ dir: '/a/b', name: 'c', ext: '.js' })` | `'/a/b/c.js'` |

---

### 🧭 四、常见使用场景示例

| 场景 | 示例代码 | 说明 |
|------|-----------|------|
| 获取当前文件的目录路径 | `console.log(__dirname);` | 当前文件所在目录 |
| 获取当前文件的完整路径 | `console.log(__filename);` | 当前文件绝对路径 |
| 拼接当前目录与子目录 | `path.join(__dirname, 'assets', 'images')` | 保证跨平台正确拼接 |
| 获取配置文件路径 | `path.resolve(__dirname, '../config/app.json')` | 转换为绝对路径 |
| 获取文件扩展名 | `path.extname('index.js')` | 返回 `.js` |
| 获取文件名（不带扩展名） | `path.basename('src/main.ts', '.ts')` | 返回 `main` |
| 获取目录路径 | `path.dirname('/users/app/file.txt')` | 返回 `/users/app` |

---

### 🧠 五、`join()` 与 `resolve()` 的区别

| 对比项 | `path.join()` | `path.resolve()` |
|--------|----------------|------------------|
| 功能 | 拼接路径片段 | 将路径解析为绝对路径 |
| 特点 | 不会自动补全根路径 | 会从右向左拼接并返回绝对路径 |
| 示例 | `path.join('a', '/b') → 'a/b'` | `path.resolve('a', '/b') → '/b'` |

---

### 🧾 六、实践技巧

1. 始终使用 `path.join()` 进行路径拼接，避免硬编码 `/` 或 `\`。  
2. 在跨平台项目中推荐用 `path.resolve()` 生成绝对路径。  
3. 配合 `__dirname`、`__filename` 可以轻松定位文件位置。  
4. 使用 `path.parse()` 和 `path.format()` 可方便进行路径结构分析与重组。  

---

### 🔍 七、简易总结表

| 分类 | 常用方法 | 作用简述 |
|------|-----------|-----------|
| 拼接路径 | `join`, `resolve`, `normalize` | 构造标准路径 |
| 路径信息 | `basename`, `dirname`, `extname` | 提取路径各部分 |
| 路径对象 | `parse`, `format` | 拆解与组合路径 |
| 系统属性 | `sep`, `delimiter`, `posix`, `win32` | 跨平台支持 |

---

> ✅ **小结：**
> - `path` 模块主要用于**路径拼接**、**解析**、**跨平台兼容**。  
> - 处理路径时不要直接写 `'/'`，应使用 `path.join()`。  
> - 结合 `__dirname` 和 `path.resolve()`，几乎能应对所有文件定位场景。


## http 模块（创建服务器应用）
```js
const http = require('http');

// 创建服务器应用
const app = http.createServer((request, response) => {
    // 只要ip和端口一致就会执行此函数
    console.log('有人请求我的服务器应用了')
    // request 客户端请求的信息

    // 解析url
    let { pathname, query } = url.parse(request.url, true);
    // 匹配到地址返回对应的内容
    if (pathname === '/index.html') {
        response.end(fs.readFileSync(path.join(__dirname, './public/index.html')))
        return;
    }

    // 处理返回给前端的内容
    // response 服务端返回的信息
    // 改变请求状态
    response.statusCode = 404;
    // 设置响应头，支持中文
    // response.setHeader('Content-Type', 'text/plain;charset=utf-8')
    response.setHeader('Content-Type', 'text/html;charset=utf-8')
    response.end('<h1 style="color:red">找不到资源</h1>')
})

// 监听服务器应用，设置端口号
app.listen(3000, () => {
    // 服务启动成功的回调函数
    console.log(`服务启动成功,可以通过 http://192.168.1.134:3000 访问服务器应用`)
    console.log(`服务启动成功,可以通过 http://localhost:3000 访问服务器应用`)
    console.log(`服务启动成功,可以通过 http://127.0.0.1:3000/ 访问服务器应用`)
})
```

### statusCode 请求的状态码
1. 200 成功
2. 301 永久重定向
3. 302 临时重定向
4. 304 协商缓存
5. 400 请求错误，例如请求方式错误或者请求参数错误
6. 401 用户信息失效，没有登录信息
7. 403 没有权限访问
8. 404 找不到资源
9. 500 服务器内部错误
10. 502 网关错误

### 响应头
- response.setHeader('Content-Type', 'text/html;charset=utf-8')
1. text/html html类型
2. text/plain 纯文本
3. text/css css格式
4. application/javascript js格式
5. application/json json格式

### ajax
```js
let xhr = new XMLHttpRequest(); // 创建请求 
xhr.open('GET', 'http://localhost:3000/list', false); // 创建连接
xhr.onreadystatechange = function () { // 响应请求
    if (xhr.status === 200 && xhr.readyState === 4) { // 请求成功
```

### 创建请求连接
- `xhr.open('请求类型', '请求地址', 同步异步); // true: 异步，false:同步`

### 完整请求
```js
let xhr = new XMLHttpRequest(); // 创建请求  xhr.readyState === 0
xhr.open('GET', 'http://localhost:3000/list', false); // 创建连接  xhr.readyState === 1
xhr.onreadystatechange = function () { // 响应请求,会执行三次
    // xhr.readyState === 2 服务端接收请求，但是没有返回结果
    // xhr.readyState === 3 服务端处理请求，结果没有返回完成
    // xhr.readyState === 3 服务端处理完成，结果返回成功，可以通过xhr.responseText获取结果
    console.log('请求状态', xhr.status)
    console.log('响应结果状态', xhr.readyState)
    if (xhr.status === 200 && xhr.readyState === 4) {
        // 获取请求结果
        let info = JSON.parse(xhr.responseText);
    }
}
xhr.send(); // 发送请求  xhr.readyState === 1
```

## npm (包管理工具)
1. node自带的包管理工具，作用：下载包、插件
2. 类似的工具：yarn、pnpm、cnpm
2. npm 官网地址 `https://www.npmjs.com/`

### npm 使用
1. `npm init` 初始化文件夹，生成 package.json，可以记录下载过哪些插件
2. `npm install` 简写 `npm i` 安装命令
- 读取当前目录的 package.json 依次安装所有依赖项
- 安装完一个包后会自动生成 node_modules 文件夹，存下载的所有包
3. `npm install --save 包名` 简写 `npm i -S 包名` 下载到生产环境依赖
4. `npm install --save-dev 包名` 简写 `npm i -D 包名` 下载到开发环境依赖
5. `npm uninstall 包名` 卸载包

### 配置淘宝镜像
1. `npm config get registry` 查看包的下载源，默认下载源 `https://registry.npmjs.org/`
2. `npm config set registry https://registry.npmmirror.com` 把下载源改成淘宝镜像地址

### 全局包
1. `npm install -g 包名` 下载全局包，在任何地方都可以直接使用此包
2. `npm uninstall -g 包名` 卸载全局包
3. `sudo npm install -g 包名`苹果电脑下载全局包需要加上 sudo
4. `npm config get prefix` 查看全局包安装位置

### 安装 node-dev
1. npm install -g node-dev
2. node-dev ./app.js  修改app.js之后会自动编译，不用每次修改都重新起服务

## 跨域
- 浏览器的同源策略: 浏览器的安全机制，为了保护用户数据安全，浏览器只允许向和当前页面地址的协议、端口、域名一致的接口发送 xhr 请求
- 跨域: 发送的xhr请求如果和当前页面的 协议、端口、域名 其中一个不一致就会发生跨域

### 处理跨域的三种方案
1. jsonp
- 缺点：只能处理get请求的跨域，需要后端修改接口代码
- 原理：利用 script 标签不会跨域的特点，动态创建 script 发送请求，后端返回一段 js 代码
```js
// 封装jsonp
function jsonp(url) {
  return new Promise((resolve, reject) => {
    const callbackName = 'jsonpCallback_' + Math.random().toString().slice(2)
    window[callbackName] = function (res) {
      resolve(res)
    }
    const script = document.createElement('script')
    script.src = `${url}?callback=${callbackName}`
    document.body.appendChild(script)
    script.onload = () => {
      script.remove()
      window[callbackName] = null
    }
  })
}
```
2. 配置允许跨域访问的响应头
- 响应头: res.setHeader('Access-Control-Allow-Origin', '*')
3. 请求代理
- 原理：利用服务器应用之间不会跨域的特点，前端页面请求前端自己的服务器应用，前端的服务器应用去请求第三方服务器应用，从第三方获取到数据后返回给前端页面
